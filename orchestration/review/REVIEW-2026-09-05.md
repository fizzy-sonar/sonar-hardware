## Findings, ordered by release impact

### R1 — BLOCKER: coupon U1 pin map is wrong on both variants

`coupons/mic-bakeoff/generate_coupon.py:84–110` defines a guessed CDCLVC1112PWR
map. TI SCAS895B section 5 assigns Y0=3, GND=4, VDD=5, GND=11, Y1=24; the
generator instead assigns GND=3, Y0=4, Y1=5, VDD=11, NC=24. The PCB pad/net
inspection confirms the error reached BOTH actual boards:

| U1 pin | TI function | Actual PCB net |
|---|---|---|
| 3 | Y0 | GND |
| 4 | GND | CLK_Y0 |
| 5 | VDD | CLK_FBR |
| 11 | GND | +3V3_MIC |
| 24 | Y1 | unconnected |

The supply is applied to a device ground pin, the intended mic-clock source is
actually a ground pin, and the intended feedback clock is a supply pin. These
boards cannot implement the specified clock tree; powering them risks an internal
supply short. This is a confirmed defect, not an outstanding datasheet preference.

Source checked live: [TI CDCLVC11xx datasheet, section 5](https://www.ti.com/lit/ds/symlink/cdclvc1112.pdf).
Repair the complete pin map, schematic, routed PCB and exports, then independently
compare all 24 pins to the manufacturer table. Do not repair only the named pins:
the generator also hard-codes routing by pad number. Owner: T-022.

### R2 — BLOCKER: full DRC finds coupon shorts that the custom checker skips

Read-only KiCad DRC with `--refill-zones` reports **82 SPH / 92 ICS violations**, zero
unconnected pads on both. Both reports identify **five `shorting_items` each**:
C1–C4 connect +3V3_MIC to GND through touching pads; R1 shorts CLK_FB to CLK_FBR.
Durable reports: [SPH](evidence-2026-09-05/sph-filled-drc.rpt) and
[ICS](evidence-2026-09-05/ics-filled-drc.rpt), copied from the current build outputs.

`generate_coupon.py:717–727` rotates the 0603 footprint while emitting pads without
their board orientation. The 270-degree capacitors have pad centers 1.0 mm apart
vertically and pad heights of 1.0 mm: their copper touches. The custom verifier
reports PASS because `verify_coupon.py:208` skips all comparisons within a single
footprint, irrespective of net. It also omits no-net pads at lines 94–96, masking
the TP6/U1-pad clearance problem reported by KiCad.

Not every DRC entry is an independent manufacturing defect: some reflect default
0.2 mm rules versus intended finer clearances. Nevertheless, actual shorting items
are release blockers. Resolve the port/anchor/hole and courtyard findings too;
waive only individually justified rule exceptions. Require full filled-board DRC
and fabricated copper/paste inspection; the geometric checker is supplementary.
Owner: T-022.

### R3 — HIGH: the advertised SRAM fallback stops when USB stalls

`gateware/rtl/pdm_stream_core.sv:51–52,94–97` gates the snapshot tap with the same
`accepting` state that permanently stops on the FT245 FIFO becoming full.
`sonar_top.sv:191–205` feeds that tap into the snapshot controller. Startup runs
once; the snapshot button does not restart capture.

Without a draining FT232H, the 16,384-frame FIFO fills in about **5.33 ms at
3.072 MHz**. A later snapshot button receives no new frames; even an immediate
snapshot cannot fill the configured 174,762-frame SRAM window before the stream
stops. Thus the Cmod's own USB-UART path is not an independent day-one fallback.

The committed review probe reproduces starvation with an eight-frame FIFO:
`taps before=9 after=9` across 100 subsequent PDM cycles. The ninth tap is also
the overflow-triggering frame: the tap's comment claiming only accepted frames
is inaccurate because its valid signal omits `!fifo_full`.

Decouple snapshot acquisition from USB acceptance and test an actual top-level
snapshot after a prolonged USB stall and with no FT clock. Keep overflow explicit
on the streaming path. Owner: T-023.

### R4 — HIGH: there is no commanded, timestamped sonar measurement

`sonar_top.sv:222–226` hard-wires TX start, frequency, amplitude and duration to
zero. This is a good idle state but means a built bitstream cannot transmit a
chirp. SRAM starts on a button, independently; `sram_snapshot.sv:141` reports
first-logical-frame zero. No implemented TX event metadata associates an emitted
waveform with received sample time. The host range estimator assumes the time
origin supplied by the synthetic fixture.

Implement a minimal arm/fire/read/status transaction, driver wake interval and
fault handling, deterministic TX/RX timestamp, waveform identity, and capture
restart. Verify through the real `sonar_top`, not only standalone submodules.
Physical synthesis/timing proof remains T-020. Owner: T-023.

### R5 — HIGH: live host transport mistakes temporary silence for EOF

`host/sonar_host/transport.py:74–80` permanently sets EOF after any empty read.
`FT232HTransport.read()` supplies `read_data_bytes(size, 4)`, which returns whatever
is available after bounded attempts; absence of payload is not a device-close
signal. A normal startup/idle interval therefore aborts the read even if valid
data arrives next. The review probe supplies `[header, empty, valid frame]` and
reproduces `stream ended after 0 frames; requested 1`.

Use explicit transport idle/deadline/disconnect semantics; test startup, bounded
timeout, partial header, unplug and reconnect. The optional sticky-status callback
has no implemented hardware control path, so it cannot yet detect physical
overflow. Source: [PyFtdi read_data_bytes documentation](https://eblot.github.io/pyftdi/api/ftdi.html#pyftdi.ftdi.Ftdi.read_data_bytes).
Owner: T-024 with T-023 status integration.

### R6 — HIGH for continuous imaging: DSP is a finite-record reference

`host/sonar_host/dsp.py:71–93` resets all CIC and FIR history on each call;
`process_payload()` unpacks and processes the whole payload. `RawCaptureStore`
retains every raw byte in memory. There is no bounded continuous pipeline connecting
transport, stateful decimation and imaging. The review probe shows identical input
split into four blocks differs from whole-record output by **0.233102** peak
normalized amplitude. This does not invalidate the finite-record demo; it prevents
using this function unchanged per live transport block.

`host/benchmark.py:29–45` times memory-backed mock ingestion only, after generating
the fixture. It measures neither USB, disk nor DSP. Its large MB/s result cannot
close the sustained capture or processing risk. Deliver stateful bounded streaming,
boundary invariance and memory/throughput measurements, followed by physical
USB+disk+DSP soak testing when hardware exists. Owner: T-024.

### R7 — Gate correction: MA40S4S rating is not a choice of interpretations

Murata's public Rev.K section 5.3 labels 20 Vp-p at 40 kHz square wave as the maximum
input voltage. Engineering should treat this as the terminal limit unless Murata
provides an explicit exception. A 12 V bipolar bridge produces 24 Vp-p; reducing
PWM duty alone does not reduce that excursion. The document's separate 24 Vp-p
qualification test does not supersede its operating maximum. A simple nominal
10 V rail also needs tolerance and overshoot margin; a series resistor requires
load/waveform analysis and measurement before it can be accepted as protection.

Source: [Murata MA40S4S Rev.K, sections 5.3 and 7.7](https://www.murata.com/~/media/webrenewal/products/sensor/ultrasonic/open/ma40s4s-e.ashx?la=en).
D013 remains proposed, with Joshua's ratification outstanding. Keep MA40S4S
disabled at 12 V and prefer the already proposed wideband TX path after its exact
part/drive rating is checked. T-025 prepares the concrete release proposal.

## Path to a useful product

First prove a repeatable physical sonar measurement. Proposed acceptance for the
first demo, **not a newly ratified requirement**: a fixed indoor reflector at
1–3 m; 20 consecutive commanded acquisitions; range error within 10 cm; explicit
failure reporting; raw captures and configuration saved for replay; a simple
range plot and approximately one update per second. Four coupon channels suffice
to establish acquisition and echo ranging; full-array bearing validation follows.

1. **T-022, first:** repair/review both coupons and their release checks. Order
   remains held until the repaired artifact is reviewed at CP-BM.
2. **T-023 and T-024:** complete the simulated arm/fire/capture/host path and build
   it on the T-007/T-020 Vivado host. USB-independent snapshots and timeout recovery
   are explicit acceptance cases. No new FPGA or EDA platform is needed.
3. **T-025:** package the actual bench path, TX part, equipment access, adapter wiring,
   capture program and complete cost before Joshua approves spending. The current
   117 dB calibrated fixture and >=500 MHz scope requirements are not satisfied
   merely by buying the listed development boards. The four-channel capture YAML
   is not an acquisition program; neither existing 24-channel default is a released
   coupon bench setup. At 4.8 MHz / 24, the sample rate is 200 kHz, not the YAML's
   fixed 128 kHz. Validate both candidates' complete acquisition chain.
4. **Bench:** validate electrical operation, one real echo, then the existing
   calibrated T-016 release gates. Do not equate a visible echo with mic release.
   Only after Joshua ratifies the MPN do T-010 → T-014 → T-015 → CP-C → layout proceed.

Window sizing needs an explicit choice: the current Pico window is only 5.333 ms
(at most 0.915 m round-trip range from a TX-aligned start, before chirp/recovery
overhead); the Cmod full SRAM window is 56.89 ms (9.76 m under the same assumptions).
PLAN's larger Pico estimates describe potential RAM use, not current firmware.

For product expectations, D001's 27.6–32 mm aperture gives a rough uniform-aperture
beamwidth scale of 22–25 degrees at 25 kHz (`0.886 lambda / aperture`). This is an
estimate, not a measured beam pattern or angular accuracy limit. The ideal 1.43 cm
range resolution from 12 kHz bandwidth does not imply centimeter lateral imaging.
Before promising an imager, measure point-spread, sidelobes, two-target separation,
off-axis response, room reverberation, direct leakage, update rate and repeatability.
The nominal +27.1 dB/person-at-10 m result still assumes unmeasured TX level,
target strength and ideal processing gain. Retain it as a sensitivity analysis.
